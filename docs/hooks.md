# Hooks

`hooks/hooks.json` registers these. The run hooks are active only while a run marker exists (`.superlite/stable.json`, `prime.md` or `pool.json`, written by the first lint). They fail open on bad input.

**Which `.superlite`.** Each session has its own (`hooks/superlite-state.sh`, the same order as `scripts/state.py`): `$SUPERLITE_STATE_DIR`; else the session's binding `~/.superlite/sessions/<session_id>`, written by `sl orchestrator set|approve|bind` and `lint --stable`; else `<CLAUDE_PROJECT_DIR or cwd>/.superlite`, unless its `session` file names another live session (one whose binding points at it). A binding counts only while no other session took the folder over (`sl orchestrator bind --force`). `session-start` exports the hook's id as `SUPERLITE_SESSION_ID` (through `CLAUDE_ENV_FILE`), so `sl` binds under the id the hooks read; on `/clear` it hands the one binding of the same Claude process (`CLAUDE_PID`, line 2 of the binding) to the new id. So sessions launched from one checkout and building in separate worktrees never share a gate, a reply log or run markers. `sl orchestrator end` archives the run markers; the run hooks stop.

- `session-start`: injects `using-superlite` at startup, clear and compact.
- `block-unsafe-kill`: always on for Bash and PowerShell; blocks killing processes by name or pattern (`taskkill /IM`, `pkill`, `killall`, `Stop-Process -Name`). Kill by PID is allowed.
- `block-coordinator-edits`: during a run, blocks the coordinator (calls without `agent_id`) from writing project code. It may write `docs/plans/**`, `docs/*/plans/**`, `SPEC*.md`, `docs/**/*.md` and `.superlite/**`; inline interpreter writes (`python -c`, heredocs, `node -e`) are judged by each writer call's own target (a literal, `Path('...')`, or a name assigned one); every `open(` must be a plain read or such a write, and a writer with an unknown target blocks. Paths with `..` segments count as project code. File APIs without a writer call (`os.replace`, `shutil.copy`) are out of its reach. Subagents always pass.
- `record-human-reply`: while the session's state is human and unapproved, appends each human prompt to `.superlite/human-replies.jsonl` (the evidence `sl orchestrator approve` checks).
- `rewrite-test-runs`: during a run, rewrites the coordinator's raw test commands (pytest, npm test, go test, cargo test, dotnet test, ...) into a background `sl run_tests --full`, and logs a `rule-rewrite` incident.
- `capture-agent-launch`: during a run, appends a `launch` record (agent id, type, model, description) to `.superlite/metrics.jsonl` after each `Agent` call.
- `capture-agent-stop`: during a run, appends a `stop` record (agent id, type, transcript path, last message) to `.superlite/metrics.jsonl` when a subagent stops.
