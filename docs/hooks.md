# Hooks

`hooks/hooks.json` registers these. The run hooks are active only while a run marker exists (`.superlite/stable.json`, `prime.md` or `pool.json`, written by the first lint). They fail open on bad input.

**Which `.superlite`.** Each session has its own (`hooks/superlite-state.sh`, the same order as `scripts/state.py`): `$SUPERLITE_STATE_DIR`; else the session's binding `~/.superlite/sessions/<session_id>`, written by `sl orchestrator set|approve|bind` and `lint --stable`; else `<CLAUDE_PROJECT_DIR or cwd>/.superlite`, unless its `session` file names another live session (one whose binding points at it). A binding counts only while no other session took the folder over: `sl orchestrator bind --force`, or without `--force` a session launched in the folder's own project (line 3 of a binding records the launch directory) when the owner was launched elsewhere, as a build session launched in a worktree takes over the planning session's folder; an owner launched in the same directory still wins. `session-start` exports the hook's id as `SUPERLITE_SESSION_ID` (through `CLAUDE_ENV_FILE`), so `sl` binds under the id the hooks read; on `/clear` it hands the one binding of the same Claude process (`CLAUDE_PID`, line 2 of the binding) to the new id. So sessions launched from one checkout and building in separate worktrees never share a gate, a reply log or run markers. `sl orchestrator end` archives the run markers; the run hooks stop.

- `session-start`: injects `using-superlite` at startup, clear and compact.
- `block-unsafe-kill`: always on for Bash and PowerShell; blocks killing processes by name or pattern (`taskkill /IM`, `pkill`, `killall`, `Stop-Process -Name`). Kill by PID is allowed.
- `block-coordinator-edits`: during a run, blocks the coordinator (calls without `agent_id`) from writing project code. It may write `docs/plans/**`, `docs/*/plans/**`, `SPEC*.md`, `docs/**/*.md`, any `docs.md` and `.superlite/**`, in the project or in a linked worktree inside it (judged from the worktree's root, as is the human gate's review plan); inline interpreter writes (`python -c`, heredocs, `node -e`) are judged by each writer call's own target (a literal, `Path('...')`, or a name assigned one); every `open(` must be a plain read or such a write, and a writer with an unknown target blocks. Paths with `..` segments count as project code. File APIs without a writer call (`os.replace`, `shutil.copy`) are out of its reach. Text inside quoted arguments or heredocs is not an interpreter call, unless a shell runs it (`sh -c`, `eval`, a stdin shell such as `bash <<EOF`, or `$(python ...)`). Relative targets are judged from the effective directory: the input `cwd` when the command holds no `cd` at all; at each `cd` when every `cd` is a plain command into the project and the command is one `&&` chain or a single leading `cd` to an existing folder (interpreter writer targets then from every directory it visits); otherwise the input `cwd` with each `cd` target judged too when every `cd` is a readable absolute target in the project, a leading `cd <absolute>` to an existing folder or plain relative `cd sub` steps, while any other `cd`, `pushd`, `popd` or `chdir`, a `cd` in a pipe or sent to the background turns the outside base off and judges from the project root, the `cwd` and each `cd` target; a `-c` or substitution body that changes directory is judged from the project root, `env -C` and `sudo -D` (read off their own option words) count as a directory change, relative `cd` steps walk from the input `cwd` and a step into a missing folder leaves the directory unknown, and while the directory is unknown a relative path with `..` blocks; the input `cwd` is taken as the shell's own directory; so writes outside the project pass; `patch` and `git apply` honour `-d` and `-C` the same way; a writer whose target starts at an absolute path outside the project passes. A stdin shell's program (the heredoc body or here-string of `bash`/`sh` with no `-c` and no script operand, with `-s`, or of `/dev/stdin`; also `source /dev/stdin` and `sudo -s`/`-i` with no command; every heredoc on a line, in order) is judged like a `-c` body, and so is the string of `env -S`; a program piped into a shell (`cat <<EOF | sh`, `echo ... | bash`) or given by process substitution (`bash <(echo ...)`) is out of reach. While it enforces, git rewrites of project files block: `git apply`, `git am`, `stash pop|apply|branch`, `reset --hard|--merge|--keep` and the forced discards (`checkout -f`, `switch -f`/`--discard-changes`, `checkout-index -f`/`-a`, `read-tree -u`) in the project, and `checkout`, `restore`, `rm`, `mv` and `clean` on a project path (judged like any write target; a folder, `.` and `clean` with no path stand for what lies in it; `restore --staged`, `rm --cached` and `-n` pass); branch moves (`switch`, `checkout <branch>`, `merge`, `rebase`, `pull`) and `git stash` itself pass. `tar -x` and `unzip` block when they extract into project code (the last `-C`, `--directory`, `--cd` or `-d`, read like getopt inside option clusters, else the shell's directory), and absolute member names (`tar -P`) block; extraction to stdout (`-O`) passes; other archivers (`7z`, `ditto`, `cpio`) are out of reach. `nohup`, `timeout`, `nice` and `exec` are skipped like `sudo` and `env`, with their own options. The guard is best-effort: it judges `-c`, stdin-shell and substitution bodies one level deep and does not parse every shell form. Accepted limits: run time grows quadratically with the number of quoted words (about 1000 reach the hook timeout, which fails open), and nested quotes inside a `$(...)` within double quotes are not judged. `sed`/`perl` `-i` (also inside a flag cluster) judge every file operand; `ruby` and `php` writers count as interpreter writers. Subagents always pass.
- `record-human-reply`: while the session's state is human and unapproved, appends each human prompt to `.superlite/human-replies.jsonl` (the evidence `sl orchestrator approve` checks).
- `rewrite-test-runs`: during a run, rewrites the coordinator's raw test commands (pytest, npm test, go test, cargo test, dotnet test, ...) into a background `sl run_tests`: named test paths go to `--fast`, a bare runner to `--full`; it logs a `rule-rewrite` incident. It denies a known runner inside `until` or `while`, a test run sent to `/dev/null`, and a subagent's bare full suite (a named file passes). A coordinator test command with a quoted argument (`"` or `'`) passes unchanged; for a subagent a quoted file name counts as a named file, a quoted flag value (`-m "not slow"`) does not.
- `compact-nudge`: on `UserPromptSubmit`, when the session is 30 minutes past its launch or last compact, adds one context line asking the agent to tell the user to run `/compact`; shown once per window (it stamps `.superlite/last-compact`). Off with `SUPERLITE_NO_AUTOCOMPACT=1`.
- `capture-agent-launch`: during a run, appends a `launch` record (agent id, type, model, description) to `.superlite/metrics.jsonl` after each `Agent` call.
- `capture-agent-stop`: during a run, appends a `stop` record (agent id, type, transcript path, last message) to `.superlite/metrics.jsonl` when a subagent stops.
- `final-review-check`: on `Stop`, blocks once per branch (recorded in `.superlite/final-review-warned`) when the branch is not the default branch (`origin/HEAD`, else `main`, else `master`; detached HEAD is ignored), changes 5 or more files or 150 or more lines against the merge-base, working tree and untracked files included (`docs/` and `.superlite/` excluded; untracked files over 1 MB add no lines), and `.superlite/metrics.jsonl` has no `superlite:final-reviewer` stop newer than the merge-base commit. The reason asks for a final review on a packet or a stated reason. Off with `SUPERLITE_FINAL_REVIEW=off`; silent when `stop_hook_active`. Not in `hooks-cursor.json`. `capture-agent-stop` records final-reviewer stops even without a run.

## Detecting an active run

For a third-party hook, use the first of these that applies (the order of `hooks/superlite-state.sh` and `state.py`). 1. `SUPERLITE_STATE_DIR`, when set, is the `.superlite` folder. 2. Read `session_id` from the hook input and read the first line of `~/.superlite/sessions/<session_id>` (`$SUPERLITE_HOME/sessions/<session_id>` when `SUPERLITE_HOME` is set) as the bound `.superlite` folder; it counts while the folder exists and its `session` file is empty or names this session (another name means taken over). 3. Legacy: `<project>/.superlite` (`CLAUDE_PROJECT_DIR`, else the input `cwd`), unless its `session` file names another live session whose binding points at that folder. No such file or folder means no bound run. A run is active while that folder holds `pool.json`, `prime.md` or `stable.json`. `sl orchestrator end` archives those markers.

Warning: checkpoint mode leaves the tree dirty during a run by design, so a Stop hook that polices uncommitted files should stay silent while a run is active.
