# Language

The tools are Python, but the project can be in any language. `run_tests` uses the project's own test command (`.superlite/test-cmd.json`, else the user-level default `~/.config/superlite/test-cmd.json`, else detection from its marker files). The probe stage (`probe_run`) is Python only.

**Xcode.** With an `.xcodeproj` or `.xcworkspace` and no `Package.swift`, set `.superlite/test-cmd.json` to `{"language":"swift","test":"xcodebuild test -scheme X {only_testing}"}`. `{only_testing}` becomes one `-only-testing:<Target>/<Suite>` per test file, by target membership (the `project.pbxproj` unit and UI test targets, `.testTarget` names in `Package.swift`); a file with no suite gets the target-wide id, and a file not in a test target runs the unfiltered command with a note on stderr. An xcodebuild failure is located at `file:line` with its suite path, a counted run covers its files, and a crash relaunch is named `<name> (crashed)`. Swift Testing (`✔`/`✘` lines) and XCTest (`Executed N tests`) output are both parsed and summed; without a command, `run_tests` prints an xcodebuild hint. Compiled stacks (swift, go, rust, csharp; `"isolate": false` in the config opts out) run `run_tests --task Tn` in an isolated tree `.superlite/trees/Tn` (newest checkpoint plus Tn's own files), so a sibling's half-edited file never breaks the compile; `sl trees clean` removes the trees at finish.

**Swift.** A `Package.swift` is detected without any `test-cmd.json`: `swift test --xunit-output {junit}`, and per-file runs through `--filter` on the test file basenames (placeholder `{names}`, e.g. `NotificationModelTests|PushPayloadTests`). `swift test` writes Swift Testing results to the `-swift-testing.xml` sidecar next to the JUnit file; `run_tests` counts every non-empty `<junit stem>*.xml` and sums them. A worktree without its own `.superlite/test-cmd.json` falls back to the main checkout's. The log and the failure tail are ANSI-free.

**User-level default.** `~/.config/superlite/test-cmd.json` (`SUPERLITE_USER_TEST_CMD` names another file) holds one entry per language, each shaped like a project file: `{"swift": {"test": "<placement-cli> test", "test_file": "<placement-cli> test {only_testing}"}, "python": {"test": "<runner> pytest", "test_file": "<runner> pytest {files}"}}`. It applies to every project without its own `.superlite/test-cmd.json` (a worktree falls back to the main checkout's first) whose detected language names an entry (`swift` also for an `.xcodeproj` or `.xcworkspace` without `Package.swift`; `python`, `javascript`, `typescript`, `go`, `rust`, `csharp`), so every checkout and worktree runs its tests through a placement CLI (a build-slot scheduler, a remote runner) instead of the raw tool. `test` is the `--full` command and `test_file` the `--fast` one, so each can go to its own machine: the single file on the worker's machine, the full suite on the remote runner. The wrapped command's output is parsed as the wrapped tool's, compiled stacks still run `--task` in their isolated tree, and a configured command never stamps the unit layer. `sl testcmd` prints the command in effect with its `origin` (the file, or `detection`); an unreadable file or an entry without `test` is skipped with a `user test-cmd.json ignored` line on stderr.

**Forecast.** The plan forecast (`sl plan_tools lint`, `schedule`, `predict`) adds the project's test-run cost: `"run_min": N` (minutes per run, both modes) or `"run_min": {"fast": N, "full": N}` in the test-cmd.json in effect (a user-level entry too), else the median `seconds=` of the newest `- tests fast|full` ledger lines in the repository's checkouts (`.superlite/progress.md`, `.superlite/runs/*/progress.md`; 3 lines at least). Each task adds its runs (fast and slow 3, build 1) times the fast minutes, less the 0.5 min a run the coefficients already hold, and lint's size band rises by the same amount; the schedule tail adds the full run. Contention scales both: the other superlite runs live on the machine (session bindings with a live pid and a run changed in the last 2 hours) share `"slots": N` build slots (default 2), and the closing full run waits for them at the full-suite lock. A task that owns only prose files (`.md`, `.rst`, `.txt`, ...) or has `**Kind:** prose` counts double time and triple calls, unless it is `Kind: mechanical`. `predict --plan` names these inputs under `live`; `SUPERLITE_FORECAST_LIVE=0` turns them off.
