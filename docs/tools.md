# Tools

Mechanical steps are scripts, not agents. Every tool runs as `<skill-dir>/scripts/sl <tool> ...`, where `<skill-dir>` is `skills/subagent-driven-development`. The `sl` launcher runs a `.sh` tool under bash and a `.py` tool under the first working Python, and exits 3 when there is none. It caches that interpreter, so each later call is one Python start (`SUPERLITE_PYTHON` skips the probe entirely). Tools that need each other import them in process instead of spawning `sl` again. Bare `sl` lists the tools, and an unknown tool name suggests the nearest. The tools are Python, but the project can be any language.

`sl` runs as an executable (the Claude Code worktree guard refuses `bash <script>`). `Permission denied` or a shell without shebang support, such as PowerShell: prefix `bash`.

| Tool | What it does |
|---|---|
| `plan_tools` | Plan lint (`--stable` freezes tasks and tiers), task graph, stubs, schedule, prune, and the `adapter`, `packet` and `contract` review subcommands. `lint --stable` first runs the start gate (`start_gate`) and exits 2 without writing `stable.json` when blocked. |
| `coverage` | Decision coverage for brainstorming's pass (`skills/brainstorming/coverage.md`): prints the `## Coverage` table skeleton, every row open (categories from that file plus the project's `.superlite/coverage.md`); `check FILE` prints the `COVERAGE:` and `NOTE:` lines lint would, exit 1 when any `COVERAGE:` |
| `wave0` | Builds the Wave 0 skeleton brief for `implementer-haiku` from the plan alone |
| `routing` | Maps each task's plan features to a tier (haiku or sonnet) using `routing.json` |
| `shape` | Build shape: contract examples, removable edges, prune, chain ids |
| `predict` | Predicts each task's time, context and cost; `--refit` fits the coefficients; with 20 history rows of the project's language (`history.detect_language`), time is scaled by their median actual/predicted ratio, clamped to 0.5–3, and the forecast names it under `language` |
| `build_prime` | Builds the shared prime that every agent reads first: slim for sonnet (rules and interfaces, no plan, no `--spec` needed), `--prime full` restores the old one with the plan and `--sections`, `--tier haiku` builds the mini prime; without `--prime`, a lane build claims a pending `experiment` (its prime, noted on stderr). The prime carries one `Root: <abs run root>` line (the plan's git toplevel, POSIX) before `Rules:`; the agent files tell agents to work and run `sl` there. |
| `task` | `task Tn --plan PLAN` prints one task's block from the current plan (no rebuild); an unknown id exits 2 and lists the tasks |
| `worktree` | `worktree ensure TOPIC [--repo DIR]` prints the absolute path of the run's own git worktree. From a linked worktree it returns that one (state `linked`); otherwise `<main root>/.claude/worktrees/superlite-<slug>` on branch `superlite/<slug>` (slug: lowercase, non-alphanumerics to `-`, at most 40 characters), created from `HEAD` (`created`) or found again (`exists`; a deleted folder is pruned and recreated; an existing branch is reused). The main checkout's branch and files never change; `.claude/worktrees/` is added once to the repository's `.git/info/exclude` (never a tracked file). No repository, a bare one or no commit yet: the start folder is printed with a stderr note (`no-repo`). A fresh worktree has no installed dependencies or ignored local files: stderr says `worktree: ignored in the main checkout, missing here: ...`, and Wave 0 adds a lockfile bootstrap step. Exit 0 ok, 1 `git worktree add` failed, 2 a plain folder sits at the target path. `worktree inplace --reason TEXT` records an in-place opt-out for an inline flow. |
| `start_gate` | Called by `lint --stable`, not run by hand. Modes, in order: `resumed` (the root's `.superlite/stable.json` exists), `no-repo`, `linked` (a linked worktree), `in-place` (plan header `**Worktree:** none`), `shared` (blocked). A shared checkout without the opt-out prints three stderr lines and exits 2: `lint --stable: BLOCKED: <root> is the shared checkout, not a worktree`, `run: <abs sl> worktree ensure <topic>` (shell-quoted; topic = plan file name without date and `.md`) and `or add **Worktree:** none to the plan header`. In every mode but `resumed` and `no-repo`, a session directory outside the run root adds a `WARN:` line (stderr) naming `EnterWorktree path=<root>` and `cd <root>`. An in-place run prints `IN-PLACE: dirty before start: <paths>` (`none` when clean) on stdout, appends the ruling `in-place run - plan header **Worktree:** none` once to `.superlite/progress.md`, and `stable.json` records `worktree` (the mode) and `baseline_dirty` (project-relative POSIX paths dirty at the first lint, without the plan's folder and `.superlite/`); later lints keep both keys. |
| `dispatch` | Ready tasks and who runs each, in one call (`next_tasks` + `assign`). A line can be a batch `Tn,Tm` of one tier, packed by predicted time and context; a critical-path task runs alone; `--batch 1` prints one task per line; without `--batch`, a run that claimed an `experiment` uses its batch |
| `pool` | Keeps `.superlite/pool.json` (never edit it by hand); without `--pool` it, `dispatch`, `assign`, `task` and `commit_task` use the session's bound run folder (as do the `--ledger` and `--log` defaults of `commit_task`, `dispatch`, `finish` and `incident`), so a cwd reset to the launch folder still finds the run's pool: `add ID --tier T [--current Tn[,Tm]]`, `busy ID Tn[,Tm]`, `free ID`, `remove ID` (prints `removed ID`, exit 2 for an unknown id; `dispatch` removes the agents it evicts itself), `list`, `sync` (real `context_k` from the agent transcript, `idle_min`, `busy` cleared by a newer stop record; `dispatch` syncs first) |
| `next_tasks` | Computes which tasks are ready |
| `assign` | Scores idle agents and picks the most relevant one |
| `commit_task` | Checks scope (a batch is released member by member: `current` keeps the rest, `busy` stays until the last), then checkpoints (default: hidden `refs/superlite/*` commits, branch untouched) or commits (autocommit on) one or more tasks' owned files; `Tn --claim F [F...] --ruling TEXT` (exactly one task, not with `--also`) records that Tn also commits F (commits nothing); a file another task claimed is left uncommitted (`left uncommitted (claimed by Tn): F`); `--also` counts for every task in the call; files a task deleted are committed as deletions; `--dispatch` also prints the next dispatch; a modified, tracked test under `tests/` that no task owns joins the task (logged); `Tn --also FILE --ruling "TEXT"` (one task) commits a file another task owns and records the ruling; a `**Ticket:** KEY` plan header prefixes messages `KEY Tn: title`; unowned `docs/**/*.md` never blocks or stages; out-of-scope files print one `hint:` line; the import check uses the `pythonpath` roots; `--also` takes several files, a file already recorded stays accepted until it changes again, and a `docs.md` in the folder of an owned path or a parent joins the task. Out-of-scope lines carry a label: `(dirty before the run)` for a path in `stable.json` `baseline_dirty`, `(changed during the run, not by a task)` when a baseline exists (also an empty one) and the path is not in it, none when there is no baseline. |
| `autocommit` | `on`/`off`/`status` opt-in real commits (`.superlite/autocommit.json`, env `SUPERLITE_AUTOCOMMIT=1`); `apply` (the plan's own `<stem>.*` files are not unrelated changes) turns checkpoints into commits on the current branch (unrelated changes stay uncommitted and are named; it refuses a checkpointed file edited since its checkpoint), one commit per task (`--no-squash`: one per checkpoint); `clean` deletes them |
| `run_tests` | Runs the project's test command (`{junit}`, `{names}` = test file basenames joined by `\|` for `--filter`; every non-empty sidecar `<junit stem>*.xml` is counted), with `--background` (prints `summary: <path>` and a `wait:` line), `--record --passed N [--failed N] [--skipped N] [--seconds S] --command CMD` writes a full summary for a run done elsewhere (failed, skipped and seconds default 0; exit 2 when --passed or --command is missing or any count is negative; `recorded`; reports only, closes no incidents; `finish` prints `tests (full, recorded)`), a rejected `test-cmd.json` warns `test-cmd.json ignored: <reason>`, then `--wait PATH` for that run's summary (bare `--wait`: the shared latest pointer); writes `.superlite/test-summary.json` (with `started`, the run's start as epoch seconds); `--task Tn [--plan P]` runs compiled stacks in the isolated tree `.superlite/trees/Tn` (the summary stays in the main `.superlite`); works from any subdirectory (runs from the folder holding `.superlite/`, note on stderr) |
| `testcmd` | Resolves the project's test command: `.superlite/test-cmd.json`, else detection (npm, go, cargo, dotnet, Python); a Python full run without testpaths runs `tests/` (else ignores `bench/`); `{only_testing}` for xcodebuild, Swift Testing and XCTest output, `isolate` flag; optional `pythonpath`: repo-relative import roots after the root and `src/`; optional `related` (template with `{src}`): `--fast` maps a source file to its test only for `.py` files or when `related` is set |
| `pyroots` | Import roots for a project: `import_roots(root, plan)` reads `pythonpath` from `.superlite/test-cmd.json`, else derives them from the plan's `Produces` names (hyphenated package directories included) |
| `pt_review` | `adapter`, `packet` (the final review packet) and `contract` (seam checks; a producer without Python sources is checked by declaration: each signature name of a Produces line (followed by `(`, `<`, `:` or `->`, or after a declaration keyword; every name of a `case a, b` list) must be declared in an owned source file, parameters unchecked; a bare name such as `xcodebuild` or `AppModel` is prose and not checked; the unquoted signature is read next to the backticked spans, and a backticked call with nothing typed, such as `NSHomeDirectory()` or `urls(for:in:)`, declares only in the item's leading list of spans, after prose it is a use and not checked). The packet diffs `<base>...<newest checkpoints.json sha>` (from their merge base, so files a mid-run fast-forward of HEAD brought in are not listed; a run file that fast-forward also changed diffs `HEAD` against the checkpoint, so its hunk and its diff-stat row show only the run's lines) when there is a checkpoint, else `<base>` against the working tree. Its source excerpts give every changed code file its first 40 diff lines before any file gets more, then fill each file up to its cap (120 lines; hooks only by the token budget); without `--max-tokens` the packet starts at 20k tokens and grows to fit those hunks, up to 60k, and `--max-tokens N` fixes the cap. The packet drops `test-failure` incidents the newest summary shows green (a later full run also closes every `run_tests` failure it does not list, `-` entries from runners without JUnit included; a run whose summary `started` is not after the incident's `epoch` closes nothing) and labels a fast summary `full suite not run yet`. Every packet item names its checker (`checker: commit_task (tool)`, `checker: T3 (agent)`); when every open item is a tool check, the header reads `REVIEW REQUIRED (tool checks only)` and asks the reviewer to confirm or dismiss each item from its excerpt; `packet --inline --spec FILE` (an inline build, no plan) never takes the fast path: section 0 shows the spec without its Review Focus (capped at 6,000 chars), the probe coverage and contract checks are skipped, and untracked files (not `.superlite/`, the spec, `--previous` or `--out`) join the diff stat and the excerpts as new files; `--previous FILE` (any packet) adds the earlier rounds' findings and fixes as section 0b (capped at 4,000 chars); a plan's `## Coverage` table rides as section 0c (plan packets only, capped at 3,000 chars); without `--max-tokens` the cap grows by these sections |
| `probe_run` | Parallel robustness probes with no agents (Python projects only) |
| `trees` | `trees.py clean` removes the isolated test trees under `.superlite/trees` (`sl trees clean`, at finish); `path Tn` prints one |
| `incident` | Records and queries the shared incident log (file, line, context; `time` as `HH:MM:SS` and `epoch` seconds): `add` (`--kind` one of the listed choices, `--help` shows them), `resolve --file F --line N --ruling TEXT [--resolution R]` (closes the open incident there: appends an entry with that location's kind, the logged file spelling and a resolved resolution, default `resolved`; no incident there exits 2 and lists the open ones), `hotspots`, `summary`; without `--log` it uses the session's bound run folder, like the pool |
| `feedback` | Superlite's own friction inbox, `~/.superlite/feedback.jsonl` per machine: `add TEXT [--kind K] [--plan P]` (text scrubbed of home paths, e-mails, tokens), `triage [--host H]... [--all]` (merges the hosts in `feedback-hosts` over ssh, groups duplicates, ranks by count, matches open issues via `gh`; entries whose id an issue or comment cites show `filed: #N` with a `sl feedback mark` line), `mark ID...`; `finish` asks for it |
| `budget` | One line of elapsed time and cost against the plan's target and cap; its coordinator cost is the run alone |
| `metrics` | Per-task time, tokens and cost from `.superlite/metrics.jsonl` and agent transcripts; the coordinator line counts the run alone, from the first dispatch (the last `Agent`/`Task` call at or before the first agent's launch or first message) to the transcript's end, with the whole session (design and planning included) under `session`; `--reconcile` compares the session total with the stream log. The report's cost split shows the coordinator's run cost, turns, context median and peak, and the session total |
| `history` | Run history: `write` rows to `~/.superlite/history.jsonl` (each row carries the `experiment` its run claimed, else null), `read`, `derive` stats, `import` bench scores |
| `experiment` | A one-shot run setting for a measurement: `set --id ID [--prime full\|slim] [--batch N] [--min-tasks N] [--runs N]` writes `~/.superlite/experiment.json`, `show`, `clear`. The next `build_prime` (lane tier, no `--prime`) of a plan with at least `--min-tasks` tasks, in a run that has not dispatched yet (no agents in its `pool.json`), claims one run under a lock and records the claim in its `.superlite/experiment.json`; that run's prime, its dispatches (no `--batch`) and its history rows follow it. Explicit flags always win |
| `graphify_gate` | Gates Graphify for search in non-trivial codebases |
| `finish` | Collects the finish summary (rulings, commits or checkpoints, test counts, open incidents); without `--ledger`/`--log` it reads the session's bound run folder, like the pool; with open incidents it prints the `incident resolve` form |
| `orchestrator` | Human or AI gate: `set`, `approve --review`, `status`, `bind` (bind this session to a `.superlite`), `end` (archive the run markers and gate files into `.superlite/runs/<time>/`) |
| `fleet` | Herdr fleet mode CLI: `on [--accounts a,b]`, `off`, `status`, `spawn --tier T`, `stop [Wn...] [--all]`; `send`, `keys` and `wait` are handled by `fleet_io` (see `docs/fleet.md`) |
| `fleet_io` | Fleet task message, `send Wn Tn [Tm ...] [--text TEXT]`, `keys Wn KEY...`, `wait [--timeout MS] [Wn...]` (prints `Wn Tn STATUS report`, `BLOCKED-UI`, `TIMEOUT`), and report extraction |
| `fleet_state` | The run's `.superlite/fleet.json`: on/off, worker ids and states (library, no CLI) |
| `accounts` | Account choice for fleet workers from `claude-profile usage --json` and `list --json` (library) |
| `herdr_client` | One subprocess wrapper over the `herdr` CLI, JSON in and out (library) |
| `backlog` | Backlog mode CLI: `status`, `plan [--tier sonnet] [--timeout-min 60] [--reset]`, `decide --print [--batch B] \| --file F`; `start`, `wait`, `answer` and `ship` go to `backlog_run` and `backlog_ship` (see `docs/fleet.md`) |
| `backlog_run` | `backlog start [B] [--cap 2] [--model opus]`, `wait [--timeout 21600] [--poll 10]`, `answer B --file F`: per batch a worktree and a lead worker |
| `backlog_ship` | `backlog ship B lock [--wait 500] \| bump [--version X] \| merge [--title T] [--body-file F] \| release [--park R]` under the machine-wide ship lock |
| `backlog_state` | `<main root>/.superlite/backlog.json`: load, locked update, startable batches, open questions, answers, status lines (library) |
| `backlog_checks` | Checks a triage proposal and a lead's question, separates batches that share a file (library) |
| `backlog_brief` | The lead brief, the triage brief and the shipped-batch summary (library) |
| `ship_lock` | The ship lock `~/.superlite/locks/ship-<repo>.lock`: acquire, release, holder (library) |
| `fleet_lead` | Argv, env and spawn of a lead worker (library) |
| `state` | `where`: which `.superlite` this session uses (`SUPERLITE_STATE_DIR`, the session's binding, else `./.superlite`; a plan resolves at its git toplevel) |

`_pyrun.py` is a shared helper, not a tool. Probes live in `probes/` with the probe pack in `probes/pack/`.

The coordinator guard (`hooks/block-coordinator-edits`) judges `cp`, `mv` and `tee` with a directory target (trailing `/`, `.` or an existing directory) by `<dir>/<basename of the first source>`, and resolves `sys.argv[N]` writer targets to the interpreter's N-th positional argument, through one `VAR=literal` assignment in the same command; anything unresolvable still blocks. `pathlib.Path('...')` and a mode-first `Path('...').open('w')` count as writer targets like `Path('...')`. It also judges a stdin shell's heredoc or here-string program, git `checkout`/`restore`/`rm`/`mv`/`clean` paths, `stash pop|apply|branch`, `reset --hard` and forced discards (`checkout -f`, `switch --discard-changes`), and `tar -x`/`unzip` targets ([hooks.md](hooks.md)).
