# Fleet mode

The user asks for fleet ("use fleet", workers in Herdr): run `"$SL" fleet on [--accounts a,b] --plan $PLAN` before the first dispatch. While `.superlite/fleet.json` says on, every superlite role runs as a worker: a real Claude Code session in a Herdr pane (worker `Wn` shows in Herdr as `sl-<repo>-<worktree>-wn`, cut to 32 characters; its pane label is `sl:<repo>-<worktree>-<task> Wn`), one account each, editing the same checkout. While fleet is on, never call `Agent` for a superlite role (implementer, fixer, package reviewer, final reviewer, researcher, checker); a hook blocks it. It reads the session's own run (from a worktree: the worktree's `.superlite`, never a binding's folder in another checkout) and skips a fleet another session turned on (`owner_session` in `fleet.json`); without a plan, `--plan` takes the state folder the block names. With fleet off every role stays an in-process Agent call. An inline build without a taskgraph starts no implementer worker (tell the user); its final reviewer is still a worker (`SKILL.md` Final review 3). Details: `docs/fleet.md`. One fleet per session: it follows the session into the run (lint's binding, or the first fleet command naming another folder moves it there; stderr says so), and before a plan, $PLAN is the worktree's .superlite folder.

Fleet covers one taskgraph plan in one checkout: several tickets go into one plan and one run, not one worktree each. Fleet asked for but `sl fleet` unknown (compare `sl version` with the session-start line) or `fleet spawn` exits 3: report BLOCKED with the exact error before any dispatch; never fall back to in-process agents. `sl feedback add` comes in addition, never instead.

## Implementers

`"$SL" fleet spawn --for-dispatch --plan $PLAN` is the one call per dispatch round, Wave 0 included (it sends `.superlite/briefs/wave0.md` as T0), instead of `dispatch` plus a spawn and a send per line. It runs `dispatch`, starts a worker for each `fresh tier=T agent=TYPE` line, sends each line's tasks (an `agent=Wn` line goes to that idle worker) and prints one `Wn Tn[,Tm] sent` line per worker; `evict=` lines go to stderr. Workers an earlier dispatch dropped from the pool are stopped too (`stopped Wn`). A prime that stalls waits up to 30 s for a late start, then is sent once more; a start that stays slow is retried once on another account (a stderr line says so). It sends every ready task (no cap) and stops each evicted idle worker (`stopped Wn` on stdout). It refuses with `BLOCKED: no ...prime.md; run build_prime --plan PLAN first` when the prime is missing. `BLOCKED: Tn[,Tm] not sent (<reason>)` (the call then exits 3) means no worker got those tasks: treat them as BLOCKED; the other lines still went out. `poll` never appears in fleet mode. Without a prime the spawn prints `BLOCKED: no <sd>/prime.md; run build_prime --plan PLAN first, or pass --brief FILE for a brief-only task outside a plan run` (exit 3). A build task outside a plan run: `"$SL" fleet spawn --role implementer --brief <abs file>` with no prime.md starts a brief-only worker: the brief is the whole task (folder, files, tests, proof), it commits with a plain `git commit`, gets no pool entry and stops after its report.

Every worker's prime can carry files to read first: a plan header line `**Read first:** a, b` or a `"read_first": [...]` list in test-cmd.json becomes a `## Read first` section of the prime.

By hand, one line: `fresh tier=T agent=TYPE`: `"$SL" fleet spawn --tier T --plan $PLAN` prints `Wn account=A pane=P agent=TYPE`; then `"$SL" fleet send Wn Tn [Tm ...] --plan $PLAN`. `agent=Wn`: `"$SL" fleet send Wn Tn --plan $PLAN`.

Fleet workers start with no MCP server (`--strict-mcp-config`), except an implementer, fixer or package-reviewer of a project that needs one: the servers its test-cmd.json `"mcp"` list names, else `xcode` (`xcrun mcpbridge`; `XcodeOpenWorkspace` and `XcodeCloseWorkspace` denied) for a Swift or Xcode project on macOS. Each server is checked before the start (a macOS GUI session; `SUPERLITE_MCP_CHECK=0` skips the check) and a usage note goes into the worker's system prompt.

## Other roles

package-reviewer, final-reviewer and checker take no `--tier` (exit 2, `<role> takes no --tier (its agent file sets the model); ...`); `--tier` works for implementer, fixer, research and writer. Every other role takes a brief file under `.superlite/briefs/` (never pasted into the send): `"$SL" fleet spawn --role R [--tier T] --plan $PLAN` prints `Wn account=A pane=P agent=TYPE`, then `"$SL" fleet send Wn --brief <abs file> [--label L] --plan $PLAN`. A one-turn worker answers once and `fleet wait` stops it. One call does all three: `fleet spawn --role R [--tier T] --brief <abs file> [--label L] --wait [--timeout 540000] --plan $PLAN` (a missing brief exits 2 before any pane; a failed send stops the worker, `BLOCKED: Wn L not sent (...)`, exit 3).

- Package reviewer: `fleet spawn --for-review Tn [Tm ...] --plan $PLAN` (or `--package X`) writes the brief, starts the worker and sends it; `fleet spawn --for-dispatch` ends with `review: Tn (<why>)` lines for committed tasks that need a review. By hand: `--role package-reviewer`; the brief holds what the review brief in `SKILL.md` holds. The reviewer fixes its own findings; outside a run it commits its own fixes with a plain `git commit` of the files it changed; an out-of-scope fix stays an open finding. A failed send is retried once (stall or slow Herdr reply). `--for-review ... --note FILE` appends the file as `## Coordinator notes` to the generated brief before the send. The brief adds a `Red runs (task reports):` section (tasks whose report shows no red run; the reviewer proves each new test can fail) and per task a `Plan contract outside Tn's Produces` section (other plan lines that name its types); `commit_task` names such a task on stderr and its `review:` line says `no red run`.
- Final reviewer: `--role final-reviewer`, a fresh worker per round: `fleet send Wn --brief <abs>/.superlite/review-packet.md --label FR<round>`; add `--full` to ask for a full review.
- Fixers: `"$SL" findings route --plan $PLAN <json paths>` prints `fixer tier=T brief=P files=F task=Tn` per finding group. Per line: `fleet spawn --role fixer --tier T`, then `fleet send Wn --brief P`. Each fix brief carries a `Reviewed version:` line naming the checkpoint (sha and `refs/superlite/<run>/<task>` ref) of the reviewed files. Escalation: the same brief to a worker one `--tier` up. A line with `task=coordinator` has a brief whose fixer does not commit: it reports `commit: held for the coordinator`, and the coordinator commits the fix itself through `commit_task` with the owning task id once that task is done.
- Research: `--role research` (read-only `superlite:researcher`): a lead's code questions go to it, one pointed brief each; a lead reads a file itself only to rule on it.
- Checker: `--role checker` (`superlite:checker`; fleet off: Agent `superlite:checker`), one turn, for a plan's `## Running-app checks` once every task is committed, before the review packet. Brief `.superlite/briefs/check-<round>.md`: the absolute `sl` path, `PLAN`, `ROOT`, the target (scheme or app, platform, device type; a web app: its start command), the build command and the `C<n>` lines. Its standing rules (own `sl-check-<worktree>` simulator, `.build/CheckDerivedData`, throwaway renders through `render_edit`) are in `agents/checker.md`. It answers one `C<n> PASS|FAIL|NOT REACHABLE` line per check and writes its screenshots and `index.md` lines into `.superlite/render/`; FAIL findings go to fixers (`fixing.md`); at freeze delete the simulators its `Simulators:` line names.
- Writer: `fleet spawn --role writer --brief <abs file> --plan $PLAN`; the brief's first `Output: <path>` line names the one file the worker may write (`--permission-mode default --allowedTools Edit(//<abs path>)`), and every other write is refused by the fleet hook. `--role writer` without `--brief` exits 2.
- Test layers, in a repo with `scripts/test_layers.py`: `"$SL" fleet run --layer headless|tui|evals --plan $PLAN` runs the layer in a shell pane; no brief.

## Waiting and acting

Herdr restart: after the Herdr server restarted (panes gone or empty), run `"$SL" fleet restore --plan $PLAN` first, before any `fleet wait`. It re-launches every worker and lead in a fresh pane with its recorded env, account, model and name, starts the agent with `--resume <session>`, and prompts a worker whose turn the restart cut. It then prints `re-arm:` lines (`fleet wait --wave ...` while a worker is busy, `backlog run`, main's re-arm, while leads exist) and `test run ended:`, `test run running:` or `test run died:` lines for background test runs; run each `re-arm:` command. A `BLOCKED: Wn not restored (...)` line exits 3: treat that worker's task as BLOCKED.

Wait once per wave: `"$SL" fleet wait --wave --timeout 540000 --plan $PLAN` returns when every busy worker has reported, or right after the first failure (a status other than DONE, DONE_WITH_CONCERNS, APPROVED or GREEN, `findings=` above 0, or ` partial`). Act on its lines, not on report text. `BUSY Wn Wm (reported: Wk <json>)` lists the workers still running and names this call's finishers; `--timeout` is in ms (a bare number under 1000 is read as seconds; `540s` and `9m` work too). Each report is returned once: `Wn <label> already collected: <json>` means another wait got it. With `--wave`, BUSY means the wait is still open. `--tests <summary path>` (repeatable; the `summary:` line of `run_tests --background`) joins a background test run: `tests <path> GREEN|RED <counts>` or `DIED`; a pending one shows as `tests:<path>` in BUSY and TIMEOUT. Run it as a background command (the harness wakes you when it ends). A lead runs it in the foreground: it never ends its turn while its workers run. `fleet wait --any` ends at the first finisher; use it only for a task on the critical path whose dependents should dispatch the moment it commits. One-turn workers are stopped by `fleet wait`. A shell loop that polls (`sleep`, `until grep`) is a defect: use the wave wait. `fleet wait --timeout 0` waits without a limit and runs only as a background command (a foreground call ends at the 600000 ms Bash limit). One wait covers one run's state dir: it waits for the busy workers of the `fleet.json` that `--plan` resolves, so a lead's workers and main's are waited for apart.

Low memory: Claude Code stops an idle session's background commands when the machine runs low on memory (`stopped because the system is running low on memory`), a background `fleet wait` too, and no worker's end reaches you then. A restarted `fleet wait` reports every worker that finished while none ran (it reads their stop records); a worker the stopped wait had already collected is no longer busy, and `fleet wait Wn` prints its `already collected: <json>` line. AI orchestrator: say so in one line and go on with `"$SL" fleet wait --wave --timeout 540000 --plan $PLAN` in the foreground (under the 600000 ms Bash limit) for the rest of the run; Claude Code never stops a foreground command this way. Human orchestrator: report what was stopped and restart it when the human says so. `/superlite:setup` offers `CLAUDE_CODE_DISABLE_BG_SHELL_PRESSURE_REAP=1`, which turns these stops off.

- `Wn <label> <STATUS> findings=<n> [concerns=N] [partial] <sd>/fleet/reports/<id>.json`: ` concerns=N` counts a report's concerns; `<id>` is the label's first comma part; ` (screen)` marks the screen fallback.
  - Task labels (`DONE`, `DONE_WITH_CONCERNS`): `commit_task` as usual.
  - `findings=` above 0 or `CHANGES_REQUESTED`: `findings route` with the JSON paths, then the fixer lines above.
  - `BLOCKED`: treat the task as BLOCKED.
  - ` partial` (a final reviewer's APPROVED that left packet lines unread): no approval; start a fresh final reviewer for the round.
  - `UNKNOWN` (no parsable report): `"$SL" fleet report Wn --plan $PLAN` prints the saved `.superlite/fleet/reports/<id>.md` (read-only; a busy worker or one with no collected report exits 1); read it once, then decide.
  - `NEEDS_CONTEXT`: answer with `"$SL" fleet send Wn --text "..."`, then wait again.
- `Wn <label> ASKED`: the turn ended without a report; the worker was asked once. Wait again; a second miss reports UNKNOWN.
- `Wn layer-L GREEN|RED exit=<n> <log path>` plus `  <last line>`: a layer result; read the log on RED.
- `Wn Tn BLOCKED-UI <screen path>`: read the screen file; answer with `"$SL" fleet keys Wn KEY...` or `fleet send Wn --text "..."`, or treat the task as BLOCKED.
- `TIMEOUT Wn Wm`: run `fleet wait` again.

`"$SL" fleet status` lists workers; `reported` means the turn ended and `fleet wait Wn` collects it (`fleet report Wn` reads it first), `dead` (also `Wn <label> DEAD` from wait) means its agent is gone: the line names the fresh `fleet spawn`. `fleet send` to a stopped or dead worker exits 2 with that spawn line. `fleet stop Wn` or `--all` closes them. At freeze, `"$SL" fleet stop --all` runs before `trees clean` (no-op without fleet mode).

Batch leads and backlog mode (`/superlite:backlog`): main reads `backlog-main.md`, a lead reads `backlog.md`.
