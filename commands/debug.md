Superlite debug mode. Problem: $ARGUMENTS

Before the first write run `<superlite skill dir>/subagent-driven-development/scripts/sl worktree ensure <topic>` and work in the folder it prints. A hook refuses edits in the main checkout once this flow starts; for a trivial change run `sl worktree inplace --reason "<why>"`. If the problem is empty, ask for it in one line (what fails, how to reproduce). Then load `superlite:systematic-debugging` and follow it: reproduce, find the root cause, write the failing regression test, fix, verify. Fix inline (fleet off): you write the regression test and the fix yourself and commit them on the worktree's branch. With fleet off, fix-only agents (`fixer-*`) run only inside a plan run, where `commit_task` has a task id to commit against. Use the project's own test command. Do not widen the change beyond the cause. With fleet on (the coordinator guard then keeps you from writing code), the diagnosis and the fix go to one fixer worker: write a brief under `.superlite/briefs/` with the symptom and how to reproduce it, the `Root:` folder, the files it may change, the test command and the line `Outside a run: commit with plain git commit`, then run `<sl> fleet spawn --role fixer --tier 3 --brief <abs brief> --wait --timeout 540000 --plan .superlite` (fixer-opus reproduces and finds the cause); a cause the brief already names takes `--tier 1` (one module) or `--tier 2` (across modules). A build task outside a plan run goes to `<sl> fleet spawn --role implementer --brief <abs brief>` instead.
